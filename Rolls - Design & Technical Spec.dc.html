Rolls

A film-photography logbook. Photographers load a roll into the app the way they load one into a camera, record the settings for every frame as they shoot, and later watch their shots surface across time and place in a living star-field called the Cosmos.

1 · Product overview

The problem. Film photographers shoot blind — there's no metadata baked into a negative, so the aperture, shutter, light, and location of each frame live only in memory or a paper notebook until the scans come back weeks later. Details get lost, and the connection between a decision made in the field and the final image is broken.

Rolls is the notebook, rebuilt as a calm, tactile app. You log each frame as you shoot it; when the roll is finished you rewind it, send it to develop, and match your scans back to the frames you recorded. Over time the app becomes a personal archive you can travel through by time (a calendar) and by place (a map that pulls back into a globe).

Design north star

Calm, analog, unhurried. The app should feel like a well-made darkroom tool — paper textures, ledger typography, film-stock color — not a busy digital dashboard. Every element earns its place; when in doubt, remove it.

2 · Core concepts & vocabulary

These are the app's proper nouns. Use them consistently in UI copy and code.

TermMeaning
RollOne roll of film — a named container with a film stock, camera body, frame capacity (e.g. 24/36), format, and a status. Carries its own cartridge icon and film-stock color.
FrameOne exposure on a roll. Holds aperture, shutter, ISO, light condition(s), a reference photo and/or a scan, location, date, and a note.
ShelfThe home screen — the ledger of all your rolls, grouped Active / Developing / Done, sortable and filterable.
CosmosThe time-and-place view. One continuous pinch-zoom: Calendar (days) → Map (places) → Globe (Earth in the stars).
The dialThe frame selector on the logging screen — a wind-on control that moves between frames, styled after a film-advance dial.
Leader / canisterThe film-cartridge iconography used throughout — the roll icon, the start/finish animations.

3 · Design system

Typography

  • Hanken Grotesk — the primary typeface. Used for the Rolls wordmark, all headings, roll titles, and body/UI text. Weights 400–800.
  • DM Mono — the ledger/label voice. Used for kickers, small-caps labels, frame numbers, aperture/shutter/ISO values, timestamps, and metadata.

Color — base (Portra, default theme)

Paper · Card · Ink · Button · Muted · Accent. Warm paper ground, ledger-brown ink, film-stock accent.

Surfaces & components

  • Ledger rows — the Shelf lists rolls as ruled rows with columns (Roll · Loaded · Frames · State), not cards. Density over decoration.
  • Roll icon — an ink-outlined film cartridge with a cap nub and a film band tinted to the roll's stock color. This is the app's signature mark and appears at every scale.
  • Film strip — the frame-logging surface. Translucent, glossy, holographic sheen on hover/tilt; evenly spaced perforations edge to edge; band color pulled from the film stock.
  • Sheets — modal editors slide in from the bottom (mobile) or the right (desktop, 400px).
  • Buttons — dark, solid --t-btn for primary actions; ghost/transparent for navigation.

Anti-patterns to avoid

No aggressive gradients, no emoji, no rounded-box-with-left-accent-border cards, no Inter/Roboto. Keep to 1–2 background tones per surface. Layout with flex/grid + gap, never inline spacing.

4 · Themes & appearance

Themes are inspired by film stocks. Each ships a light and a dark variant. Appearance is chosen independently: System (default — follows the device), Light, or Dark. All colors resolve through CSS custom properties (--t-paper, --t-ink, --t-btn, …) so every screen re-inks live when the theme changes.

5 · Screen-by-screen spec

5.1 Shelf (home)

  • Ledger of all rolls in three groups: Active, Developing, Done.
  • Columns: Roll (icon + name) · Loaded (start date) · Frames (shot/capacity) · State.
  • Sort/filter bar: tap Roll → A–Z then Z–A; tap Loaded → oldest→newest then reverse. Default sort is newest first.
  • Swipe-right to delete a roll (reveals a red Delete; confirm dialog before removal). Same on desktop for consistency.
  • Load a new roll is the primary action, pinned bottom (mobile) / in the pick-a-roll space (desktop).
  • Desktop: a left rail lists rolls; selecting one expands its frame-logging view in place. The rail slides fully off-screen when a roll is open. Before any selection, the space reads "Pick a roll to start logging."

5.2 Frame logging

  • The film strip shows the current frame; the dial winds between frames (drag or ‹ › — ticks sit inside the ends so first/last frames stay visible).
  • Per frame: Aperture, Shutter, ISO (wheel pickers), Light (multi-select chips + a ＋ to add/edit/delete custom conditions; defaults are locked), reference photo and scan slots, location, and a note.
  • Winding past the last frame opens the Roll Summary → Mark as Done / Send to Developing.
  • A way back to the opening screen is always present.

5.3 Load a new roll

  • Choose film stock, camera body, frame count (or custom), format.
  • Start mode: Fresh roll (frame 1) or Start from a frame of the user's choice.

5.4 End of roll → Developing → Scans

  • Roll Summary: roll name, frames · date span · locations · film, and a thumbnail grid.
  • Done → returns to the Shelf marked Done.
  • Developing → a rewound canister in a Developing section ("Rewound {date} · at the lab").
  • Scan matching: add multiple scans; they fill frame slots in shooting order. Blocks can be drag-reordered, and dragged down onto a trash target to clear a wrong image. On confirm, the roll is marked Done.

5.5 Cosmos (Calendar → Map → Globe)

  • One continuous pinch-zoom journey; no slider. Scroll months in the Calendar, zoom out into the Map, keep zooming out into the Globe.
  • Calendar: month cards on a star field (paper-translucent, no borders). A day with a frame shows its image; a small glowing dot marks days a roll was started (color pulled from that roll; cycles if several). First tap selects/shows the day; second tap opens that frame.
  • Map: photos appear where they were taken (auto GPS + manual override). Tap a stack → expand a photo → "Go to this frame."
  • Globe: real 3D Earth (blue-marble texture) adrift in the stars; drag to spin; tapping a photo card flies into the Map at that location.
  • Star field: dense sharp stars, with rare random comets / meteors / phenomena. Aesthetic = paper-meets-space, dark blue/black (never brown), calm.
  • Navigation icons follow the destination's look: an animated mini-globe to enter the Map, an animated mini-calendar to return to today. Chrome (‹ Shelf, title) aligns to the top on desktop, clears the status bar on mobile.

5.6 Auth

  • Sign in, Create account, Reset password. Email + password, with Google / Apple providers to follow.
  • Split layout on desktop (brand panel + form card, centered); single column on mobile.

5.7 Settings / Account

  • Edit profile (name in Rolls, account name, profile image) · Default film · Units · Choose theme (+ appearance) · Export library · Sign out.

6 · Interaction & animation

  • Start a roll: the leader tongue pulls out of the cartridge (the app's roll icon), frame 01 popping onto the strip. Quick and snappy. Background desaturates while it plays; no modal card.
  • Finish a roll: the leader pulls taut, then winds rapidly back into the cartridge, carrying the roll's final frame number (adapts to that roll's capacity).
  • Dial feedback on wind, on both mobile and desktop.
  • Cosmos transitions are zoom-driven and continuous, not fades.
  • Chip rows and wheel pickers: drag to scroll, tap to select — a drag never mis-fires a selection.

7 · Data model

Three core entities. A user owns many rolls; a roll owns many frames.

EntityKey fields
profileid (→ auth user), display_name, account_name, avatar_path, default_film, units, theme, appearance
rollid, owner, name, film_stock, camera_body, format, capacity, shot_count, status (active / developing / done), started_at, rewound_at
frameid, roll_id, index, aperture, shutter, iso, light[] , note, lat, lng, taken_at, reference_path, scan_path

Light conditions: default set is fixed; user-created conditions are stored per profile so they persist and can be edited/deleted.

8 · Accounts & sync (Supabase)

Supabase (hosted Postgres + Auth + Storage) is the recommended backend. A signed-in user's rolls and frames — including reference and scan images — load on any device.

  1. Auth: email/password to start (maps to the three Auth screens); add Google & Apple providers later.
  2. Tables: profiles, rolls, frames (keys as in §7).
  3. Storage: a private frame-images bucket; rows store the path, the app requests signed URLs.
  4. Row-Level Security (required): every table restricted to owner = auth.uid().
  5. Client: Supabase JS client with the project URL + anon key.

Next deliverable

A hand-off doc with paste-ready SQL (CREATE TABLE + RLS policies), bucket setup, and auth wiring. To be produced when we enter the build phase.

9 · Platform & build plan

Goal: ship to the Apple App Store, Google Play, and the web, with Windows (Microsoft Store) as a later target. One codebase serves all of them.

Recommended path

  1. Lock the design here (this project) — it is the source of truth for look, copy, and behavior.
  2. Build the functional app in a real code project: React (web) + React Native / Expo (iOS & Android), or a shared framework, wired to Supabase. Expo makes App Store + Play Store builds and over-the-air updates straightforward for a first-time shipper.
  3. Web: the same React UI deployed as rolls.app; can also be a PWA.
  4. Windows: reach it later via the web/PWA or a wrapper — don't let it gate the mobile launch.

Why not design in v0 / a code tool now?

They build code from prompts; they don't hold this darkroom-ledger design system. Move to code only for the functional build — after the design is locked here.

Accounts needed

Apple Developer Program ($99/yr), Google Play Console ($25 once), a Supabase project, and a domain for the web app.
